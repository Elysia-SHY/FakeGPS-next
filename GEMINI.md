# Project Rules - FakeGPS-next

## Mandatory Design & Copywriting Standards (taste-skill)

This project strictly adheres to **taste-skill** (design-taste-frontend / anti-slop) guidelines across all frontend code, UI layouts, documentation, README files, and changelogs:

1. **Anti-Default Discipline**:
   - Avoid generic AI clichés: no arbitrary purple/neon gradient meshes, no repetitive 3-column card dumps, no hand-rolled fake screenshot divs, and no robotic marketing buzzwords.
   - Adhere strictly to the project's **Apple Human Interface Guidelines (HIG)** design system (SF Pro typography scale, dynamic Light/Dark OLED color palettes, liquid glass frosted capsules, 16dp rounded cards, and 0.5dp hairline dividers).

2. **Typography & Copywriting Rigor**:
   - Maintain a crisp, intentional hierarchy: high-contrast headings, compact value propositions, purposeful whitespace, and precise technical language.
   - Use high-signal feature matrices, structured bento sections, and clean architecture flowcharts.
   - Zero-slop audit: ensure all text is concise, authentic, grammatically immaculate, and free of empty AI filler phrases.

3. **Always-On Skill Mandate**:
   - In all current and future tasks involving UI design, user-facing text, README introductions, changelogs, and release assets, always activate and follow the 	aste-skill rules defined in .agents/skills/taste-skill/SKILL.md and ~/.gemini/config/skills/taste-skill/SKILL.md.
